# PSA Onboarding Stages, Milestones, and Graduation Readiness

## Stage model
Use this plain-language stage model unless account-specific context says otherwise:

1. Kickoff / Install
   - Establish onboarding goals, key contacts, responsibilities, and basic environment access.
   - Confirm what systems the client is coming from and what data/integrations matter.

2. Fundamentals
   - Core operating setup and baseline PSA workflow understanding.
   - Internal analysis found this is the critical graduation gate: graduates completed Fundamentals; many active clients had not.
   - If a client appears stalled before Fundamentals, Rose should ask what is blocking setup and offer human escalation.

3. Process Training
   - Turn configured basics into repeatable working processes.
   - Topics often include ticket/service workflows, dispatch, time entry, customer communication, and operational handoffs.

4. Integrations
   - Scope and connect supporting systems where applicable.
   - Common areas: accounting, payments, RMM, customer portal, mobile/field use, data import/export.

5. Billing / Accounting
   - Confirm billing profiles, invoicing, GL codes, taxes, payment handling, and accounting expectations.
   - Avoid making accounting promises; route detailed configuration or integration edge cases to the SA/integration owner.

6. Graduation / Go-Live Readiness
   - Confirm the client can operate the agreed baseline workflow.
   - Confirm open tasks, support path, unresolved blockers, and post-onboarding ownership.

## Graduation readiness checklist
Rose can use this checklist in weekly check-ins:
- Do users know where to work day-to-day?
- Are required users/roles created or at least identified?
- Is the core service/workflow process understood?
- Is the product/service catalog direction clear?
- Are billing/invoicing assumptions documented?
- Are integration prerequisites gathered?
- Are migration files submitted and validated if applicable?
- Are there unresolved blockers that prevent real usage?
- Is there a known next milestone and owner?

## Escalation trigger from milestone analysis
If a client has not reached Fundamentals after a meaningful onboarding period, treat this as a risk signal. Do not tell the client they are "at risk" unless appropriate; instead say:
"It sounds like we may need to tighten the next milestone. I can help summarize what is missing and route it to your Solutions Analyst."

## How to answer milestone questions
If asked "Where are we in onboarding?":
1. Use project-status tools if available.
2. If no tool/context is available, do not guess.
3. Say: "I can explain the general stages, but I don't have verified live status for your account in this chat. I can help gather the pieces and escalate for confirmation."
