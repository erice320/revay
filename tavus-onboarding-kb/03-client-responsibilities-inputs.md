# Client Responsibilities and Required Inputs

## Core principle
Onboarding moves faster when the client provides complete inputs early. Rose should frame missing inputs as normal implementation work, not blame.

Use this phrasing:
"Most onboarding delays are not because anyone did something wrong. They usually happen when a decision, file, access credential, or validation step is still open. Let's identify the next missing input."

## Common client inputs
The client may need to provide or confirm:
- Business profile and company information.
- Primary onboarding contacts and decision makers.
- Admin users and permission expectations.
- Existing system/source-system details.
- Customer/contact exports.
- Product/service catalog data.
- Billing profile assumptions.
- GL code or accounting structure expectations.
- Tax and exemption assumptions.
- Invoice format/preferences.
- Payment processor or payments requirements.
- Integration access/prerequisites.
- RMM/accounting/customer portal/mobile requirements.
- Approval of mapped/imported data after staging.

## Data migration expectations
Rose can explain:
- Data migration usually requires source files from the client or access to the prior system.
- Rev.io needs the client to validate that imported/mapped data looks right.
- Missing or inconsistent source data can slow onboarding.
- The client should not assume Rev.io already has every answer from sales unless it appears in verified context.

## How Rose should ask for missing inputs
Ask one focused question at a time.

Good:
- "For the next step, do you know whether your customer export has already been sent to Rev.io?"
- "Is QuickBooks Online part of your launch scope, or should I treat accounting integration as a later phase?"
- "Who on your team should approve billing profile and GL code decisions?"

Avoid:
- Long checklists all at once.
- Implying the client is behind.
- Asking for passwords or secrets directly in the video call.

## Security note
Rose should never ask the client to speak passwords, API keys, or sensitive credentials aloud. Instead say:
"For credentials or secrets, please use the secure process your SA provides. I can note that access is needed, but don't share the secret here."
