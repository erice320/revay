Company-wide agent coordination substrate

Council v2 +
Notion Vault

A shared, evidence-backed coordination system for bounded executive work: board prep, executive offsites, customer risk reviews, product launch readiness, and the Revay Command Center.

The problem

Specialty agents know their domains. Executives need the whole business.

Today’s failure mode

  • Context lives in separate agents, systems, chats, and memories.
  • Cross-functional work turns into meetings or loose chat threads.
  • Evidence disappears, assumptions harden, and actions get detached from sources.

What leadership actually needs

  • A 360-degree view from Sales, Product, CS, Support, Onboarding, Finance, Ops.
  • Source-backed risks, tensions, options, and actions.
  • A durable record that humans and agents can inspect later.
The idea

Council v2 is not a chat room. It is a bounded coordination protocol where agents submit structured, source-backed domain inputs into a shared Notion vault.

Bounded Packet→Agent Inboxes→Outbox Contributions→Synthesis→Decision + Actions
The design shift

Notion as an Obsidian-style coordination vault

Human-readable

Page tree, packet files, contribution pages, synthesis notes, decisions, actions.

Agent-queryable

Lightweight inbox/outbox databases act as queues without overbuilding the schema.

Durable

Evidence, dissent, failures, decisions, and actions survive chat threads and session resets.

Core unit of work

Coordination Packets

Each packet defines

  • Objective and business context
  • Scope and out-of-scope
  • Required contributors
  • Decision owner and synthesizer
  • Deadline / SLA
  • Output contract and close condition

Good packet examples

  • Board meeting risk scan
  • Executive offsite themes
  • PSA adoption blocker review
  • Customer churn root-cause review
  • Product launch readiness check
Agent behavior

Agents own their inboxes and outboxes.

1. Read

Find assigned work in the agent inbox. Read the packet. Stay inside the requested domain lens.

2. Contribute

Write one source-backed outbox page using the standard contract.

3. Preserve

Do not edit other agents’ contributions. Do not mutate the master packet. Preserve dissent.

Contribution contract

Every answer has the same shape.

This makes outputs synthesizable without forcing every agent into one brittle database schema.

{ "packet_id": "PKT-260528-OFFSITE", "agent": "Product Agent", "signal": "What this domain sees", "risk": "What could go wrong", "recommendation": "What to do next", "confidence": "low | medium | high", "evidence": [{ "source_system": "...", "record_count": 0, "status": "success | partial | failed", "url_or_id": "..." }], "dependency_or_ask": "..." }
Data integrity

A failed retrieval is acceptable. A fabricated answer is not.

Required

  • Source system
  • Timestamp
  • Record count when applicable
  • Retrieval status
  • Raw error if failed
  • Confidence and caveats

Forbidden

  • Inventing missing facts
  • Implying stale data is current
  • Treating non-response as agreement
  • Averaging away dissent
  • Letting chat become the system of record

Relationship to Command Center

Council v2 is the substrate. The Command Center is the surface.

Packets→Contributions→Syntheses→Insight Ledger→Action Queue→Executive Cockpit

The Command Center should not be built on loose chat summaries. It should be built on durable packets, evidence-backed contributions, decisions, and action outcomes.

What counterparts need to approve

The ask is small: one agent inbox, one outbox, one contract.

Human owner

Agree where their agent participates and which domains it represents.

Agent setup

Load the onboarding brief and configure access to its inbox/outbox.

Pilot packet

Run one bounded, high-value packet before expanding company-wide.

Rollout plan

Phase 1 — Vault skeleton

Protocol, packet template, contribution contract, inbox/outbox queues.

Phase 2 — Revay dry run

Validate structure, evidence contract, status flow, and synthesis format.

Phase 3 — One partner agent

Bring in one counterpart agent and capture friction.

Phase 4 — Multi-agent pilot

Run offsite prep, board risk scan, or PSA retention review.

Recommended sharing package

Protocol spec

Full Notion vault design, templates, lifecycle, permissions, and rollout path.

Agent brief

Short instruction file agents can ingest directly before participating.

Bottom line

Council v2 turns specialized agents into a company-wide operating intelligence network.

Not by making them chat. By giving them a shared vault, bounded packets, evidence contracts, and a durable path from domain knowledge to executive decisions.
