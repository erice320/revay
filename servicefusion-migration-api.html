Overview

ServiceFusion Open API

ServiceFusion is a cloud-based field service management (FSM) platform targeting residential and commercial service contractors. Their Open API provides programmatic access to the platform's core entities — customers, jobs, estimates, technicians, and equipment — enabling migration, integration, and automation workflows.

⚠️
Pro Plan Required. The ServiceFusion Open API is only available to Pro plan subscribers. Any customer migrating to Rev.io PSA will need active Pro access to extract their own data via API. Source ↗

Authentication

OAuth 2.0 — Two Grant Types

ℹ️
For a migration tool, Client Credentials Grant is the simpler path — no user redirect needed, pure machine-to-machine. Use Authorization Code (Connected Apps) if you need per-account scoping with revocable tokens.

Option 1 — Client Credentials Grant Verified

Navigate to: My Office → Developer Settings → API Credentials to retrieve Client ID and Client Secret.

POST https://api.servicefusion.com/oauth/access_token Content-Type: application/json { "grant_type": "client_credentials", "client_id": "YOUR_CLIENT_ID", "client_secret": "YOUR_CLIENT_SECRET" }

Option 2 — Authorization Code Grant (Connected Apps) Verified

Navigate to: My Office → Developer Settings → Connected Apps → Add New OAuth App → provide app name + redirect URL → get unique Client ID + Secret per app.

POST https://api.servicefusion.com/oauth/access_token Content-Type: application/json { "grant_type": "authorization_code", "client_id": "YOUR_CLIENT_ID", "client_secret": "YOUR_CLIENT_SECRET", "code": "AUTH_CODE", "redirect_uri": "https://your-app.com/callback" }

Token Refresh Verified

POST https://api.servicefusion.com/oauth/access_token Content-Type: application/json { "grant_type": "refresh_token", "refresh_token": "YOUR_REFRESH_TOKEN" }

Using the Token

Authorization: Bearer <ACCESS_TOKEN>
⚠️
Token Expiry Known Issue. Access tokens expire and refresh logic must be implemented. Real-world reports (Zapier community) confirm tokens can expire unexpectedly in Authorization Code flows. Build auto-refresh into any migration script from the start.
Rate Limits

0.5 Requests / Second Verified

ServiceFusion enforces a hard cap of 30 requests per minute. Exceeding it returns 429 Too Many Requests with a Retry-After header.

Relative throughput: SF (30/min) vs typical REST APIs (100–1000+/min)

Migration Considerations

Key Factors for SF → Rev.io Migrations

1. Pro Plan Gate

The migrating customer must be on SF's Pro plan to have API access. If they're on Starter/Basic, they cannot extract data via API. Confirm plan status before scoping the migration.

2. Rate Limit Bottleneck

At 30 req/min, a full data extraction (customers + jobs + equipment) for a mid-size account with 5,000 records will take 15–30 minutes. Plan for overnight extraction runs on large accounts. Never run extraction during customer business hours without their sign-off.

3. No Bulk Export Endpoint

There's no equivalent to a database dump or CSV export via API. Everything must be paginated through, entity by entity. Build checkpointing into the migration script so a failed run can resume from where it stopped.

4. Field Schema Requires Hands-On Verification

Official SF API docs are JavaScript-rendered and were not accessible via scraping. Before building field mappings, run GET /v1/customers and GET /v1/jobs against a test account and map actual JSON keys to Rev.io fields.

5. Contact Data Structure Unknown

Unlike ConnectWise (separate /contacts endpoint), SF may embed contact info within the customer object. If true, contact extraction is bundled with customer extraction — but you'd need to confirm whether multiple contacts per customer are supported.

6. Historical Job Data Volume

SF customers often have years of job history. A 5-year-old account could have 10,000+ jobs. Decide with the customer what historical depth is needed — migrating all history may not be necessary or practical.

7. Rev.io Community Thread

Rev.io's community has a dedicated thread: Service Fusion Data Migration to Rev.io — requires login. Worth reviewing for known gotchas and customer-shared learnings before building. community.rev.io ↗
