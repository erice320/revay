Overview

What You're Working With

API Type

REST + JSON

Standard HTTP verbs. OpenAPI (Swagger) schema available. No GraphQL or SOAP for external integrations.

Access Model

Customer-Credentialed

No third-party admin access. The customer generates API keys in their own CW Manage instance and provides them.

Rate Limits

No Hard Cap

Max 1,000 records/request. No documented req/sec limit — but add ~100ms delay between requests during bulk export.

⚠️ communicationItems — Critical

There is no top-level email field on Contact. All emails and phones live in this array.

[ { "type": {"name": "Email"}, "value": "john@acmeit.com", "defaultFlag": true, "communicationType": "Email" }, { "type": {"name": "Direct"}, "value": "555-867-5309", "defaultFlag": true, "communicationType": "Phone" } ]
Extraction Logic

Filter communicationType="Email" where defaultFlag=true for primary email.

Filter communicationType="Phone" where defaultFlag=true for primary phone.

Setup & Gotchas

Customer Steps + Builder Notes

Customer Setup in CW Manage
1

Create API-Only Member

System → Setup Tables → Members → New → type: API Member

2

Assign Inquire Permissions

Companies/Company Maintenance • Companies/Contacts • Companies/Company Sites • Finance/Agreements (if needed)

3

Generate API Keys

Members → API Keys tab → Add Key → copy public + private key

4

Provide to Rev.io

Company ID + Public Key + Private Key. Rev.io supplies Client ID.

⚠️ Critical Builder Gotchas
!

No top-level email on Contact

communicationItems[] is the only source for emails & phones — do not look for a root-level email field, it doesn't exist.

!

Preserve identifier as external key

company.identifier is the unique account code (e.g. "ACME-IT"). Store it in Rev.io as the external reference.

!

Sites are a separate endpoint

Company has a site reference but full branch list requires /companies/{id}/sites.

!

Always filter soft deletes

deletedFlag=true (Company) and inactiveFlag=true (Contact) — filter both unless you want historical records.
